# 整文件重复内容与有界分帧（DEV-036）

2026-11-27，主Agent（Claude），无委派。状态：执行者报告通过，**未经独立审计**；**只做测量，不改格式，不写归档**。

## 问题

有界固实（例如 32 MiB 一帧）比整段固实大，原因之一可能是：内容完全相同的文件落进了不同的帧，编码器在一帧里看不见另一帧的副本。DEV-033 里 BCJ 打乱重复副本的匹配后，体积涨了 4.3%，说明重复内容的影响不小。

本实验要回答两个问题：
1. 整文件完全相同的副本有多少？其中多少分散在不同帧里？
2. 如果归档能用"与前面某个文件相同"的引用代替副本，最多能省多少？

## 方法

- **工具**：研究命令 `dup-probe DIR VARIANT LIMIT`（[dup_probe.hpp](../../tools/dup_probe.hpp)）。
  - 文件按路径顺序作为一组，切帧方式与 `recipe-pack` 的 `g1-r0` 相同；
  - 判定重复：先按大小与 CRC32C 分桶，再逐字节比较；以第一次出现的文件为原件，空文件不算；
  - 第一份副本落在另一帧的，计为"跨帧"重复；
  - 分别压缩原树（baseline）和去掉全部重复后重新切帧的树（dedup），每帧都解回来比对，报告两者的帧字节数。
  - 第二版（schema r1，见"dup-local-dev-r1"一节）加了 `dedup_same_cut`：保持 baseline 的帧划分，只从各帧里删掉副本。这样能把"去掉副本"和"帧边界移动"两个效果分开。
- **口径**：
  - 比较的只是帧载荷，不含清单等元数据；
  - 真正去重的格式还要为每个重复文件记一条引用（例如原件的序号），每条几个字节，相比节省的量可以忽略。这是估计，未实现。
- **测试**：`research.codec_probe` 用一个答案已知的小树检查。
  - 在 7 MiB × 3 的树里加一份同帧副本、一份跨帧副本和两个空文件，要求统计数、帧数和 raw 字节完全符合预期，且 dedup 更小；
  - 非法的帧上限和算法名都被拒绝。
- **构建验证**：MSVC 0 警告、`research.codec_probe` 通过；WSL GCC Release 51/51、Clang ASan+UBSan 22/22。

**读法**：

- **整帧**：去重几乎省不了什么，所有副本都在同一个窗口里，编码器自己就能找到。
- **32 MiB 分帧**：去重能找回大部分分帧损失。
  - dev 全部、LZMA2-9e：分帧比整帧大 5.33%（37 237 954 对 35 354 598），去重后只大 1.29%（35 809 657）；
  - native-bin：去重后的 32 MiB 分帧（4 839 055）与整帧相同或略小。
  - 也就是说，这棵树上分帧多出来的体积，大部分是被切开的重复副本，不是窗口变短本身。
- **同帧副本也有代价**：native-bin 有 26.07 MB 重复，跨帧的只有 5.89 MB，但去重省了 23%。原因之一是剩下的 20 MB 同帧副本占了帧容量：baseline 要 3 帧，去重后 2 帧就装下了，原本被切开的内容又回到了同一帧。这是推断，未逐帧核对。

## 结论与限制

- **重复在真实的包缓存 / 工具链目录里很常见**：
  - 字节占比：cargo 11%、npm 10%、rustup 3%，MinGW 工具链（native-bin）39%；
  - 其中跨 32 MiB 帧的部分，是有界分帧真正丢掉的。
- **去重的收益**（32 MiB 分帧，保持原帧）：
  - 有跨帧副本时明显：append-r1 dev −3.8–4.0%，cargo −5.8–6.0%，native-bin −23%；
  - 副本大多在同帧时很小：rustup −0.1%；
  - 没有重复时为 0（印度两棵树），不带来代价。
- **整帧时去重几乎无用**（0.02–0.84%）：编码器本来就看得见同一窗口里的副本。
- **意外发现：帧边界放在哪里也很重要。** 同样的内容，只改切点，完整帧字节就能差约 3%。现在的切法只看路径顺序和字节上限，完全不看内容。
  - "按内容选切点"是一个独立的研究方向，可能和去重一样值得做；
  - 它不改格式（帧表本来就记录每帧的范围），只改写入策略。不过确定性要求同样的输入必须切在同样的位置，切点规则要进入配方 / Seed 才能保证"标签真实"。
- **限制**：
  - dup-local-dev-r1 只代表开发者机器上的包缓存和工具链，只在本机评估；
  - rustup 样本偏大文件；
  - 每组只跑一次，但大小与时间无关，可以复现；
  - 近似重复没有测；CLion 诊断未运行（MCP 连接失败）。
- **可能的后续**（需要用户决定）：
  1. **去重格式 ADR**（C 级）：加"引用已有文件"条目；要处理跨代引用、索引式提取跟随引用、合并时重新判定、原件损坏会波及所有引用。
  2. **按内容选切点的研究**：先测量，例如在路径顺序上找"相似度低谷"作为切点，看能否稳定省下这约 3%。
  3. 两者可以叠加：先去重，再按内容切帧。
