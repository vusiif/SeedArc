# 速度、压缩率与损坏恢复的联合目标

2026-11-24，用户在DEV-020运行后明确校正优先级。本文件是当前主研究方向；用户原稿、既有负面结果保留。

## 主目标与比较方法

目标是接近成熟固实方案的压缩率，同时提高速度和安全性；或在较快压缩速度下，取得优于相同压缩时间内其他算法的完整大小。不能只拿对手最强的一项作判据，也不能增加大量搜索时间后只报告少量体积收益。

- **接近完整大小时比较速度**：编码、解码、追加 / 更新分别计时。规划 / 搜索、训练、编码、索引 / 校验和写出计入对应生命周期成本；首次规划单列并作可追溯摊销。
- **相同实际时间预算时比较大小**：同数据、主机、Release、线程及内存边界，比较预算内实际产出且验证通过的最小完整归档。编码字节预算用于解释搜索，不能代替时间预算。超时未产生合法包记为未完成。
- **相同故障时比较恢复性**：固定损坏、截断、缺卷条件，报告检测成功率、受影响文件 / 原始字节、逐字节核验的恢复量、恢复耗时和冗余开销。帧小不自动证明可恢复；头部 / 索引损坏也须覆盖。

这里的安全主指标是数据完整性、损坏隔离和恢复能力；内存、路径、资源安全始终是底线。Seed不是密钥，CRC不当认证加密。固实作为强压缩率参考，不预设某算法对所有数据都必然最佳。

## 用户可选择的取舍与完整使用周期

用户进一步明确：重点是以少量牺牲、甚至不牺牲，换取明显优势；体积略大但速度显著更快、损坏隔离更好、单文件提取更快或补加新文件更快，都可能是有价值的方案。用户可以优先速度、体积或其他使用体验，不由程序替所有人固定同一种权重。这是产品 / 研究目标，尚未实现为用户界面或配置接口。

选择应围绕“优先目标＋可接受代价范围”，先用可理解的偏好表达，再映射到具体计划。例如优先速度并限制包增幅，或优先体积同时限制总压缩时间；频繁追加、频繁单文件提取和较强恢复需求也应影响选择。预设名称、默认权重和数值门槛待实测后确定，不把示意值当性能承诺。数据正确性与工程安全底线不作为可牺牲项，恢复冗余强度可以比较取舍。

评价覆盖整个使用周期，而非只看首次打包：

| 场景 | 主要测量 | 必须同时计入的代价 |
| --- | --- | --- |
| 首次压缩 / 全量解压 | 完整包大小、时间、CPU / RSS | 规划、试压、训练、索引、校验与写出 |
| 单文件提取 | 首个文件可用时间、提取时间、实际读取 / 解码字节；固定文件集合的分布 | 索引加载、额外解码量、缓存条件、定位元数据体积 |
| 补加新文件 | 追加延迟、读写与重压的旧字节、完整包增长 | 新帧 / 索引 / 旧尾部开销，多轮追加的累计时间与体积 |
| 损坏 / 缺卷恢复 | 受影响范围、可核验恢复字节与时间 | 冗余、检查点、索引保护的完整体积 / CPU成本 |

单文件提取和补加新文件是并列核心场景，不能只优化其中一个。提取不能仅计解码目标文件的最后一步；追加不能隐藏全量重压或定期整理的成本。首次构建、每次追加、必要整理和后续提取要分别报告，并按事先登记的使用频率给出生命周期成本；不把重压成本挪到另一步来制造优势。补加新路径与修改 / 删除已有路径是不同契约，未实现的更新功能不得冒充已支持。

优先保留以小代价换取大优势的实测方案，同时寻找各项都不退步的改善。若某方案在同条件下各项都不优于另一个、且至少一项更差，不作为推荐取舍；若各有优劣，让用户按需求选。所有“略大”“快很多”“更易恢复”等表述须有完整大小、实际时间、解码量或恢复量支撑；没有证据时只作为待验证目标。

## 下一阶段顺序

1. **先建立强基线曲线**：复用Store / Zstd / LZMA2适配层，比较低、中、高档的速度与完整大小；候选档位在新dev测量前登记。整段固实、有界分段都作对照；单线程主表，并行另表，同时计CPU总成本 / RSS。不用较弱逐块Seed对比强固实，不只选极慢最高档或极快低压缩档作唯一对手。
2. **分段与复用边界优先**：研究有界固实帧、文件分组、稳定追加、局部重压范围和可选恢复元数据，量出增加多少完整字节能换来多少压缩 / 追加 / 单文件提取速度与损坏隔离。先简单可验证，不扩Seed位数或人为耦合空间来制造复杂度。
3. **Seed描述 / 选择 / 复用具体计划**：使用被实测支持的策略，保留零搜索强默认和廉价复用；同计划显式表示作对照。搜索成本全部计入，只有联合取舍改善才优化搜索。
4. **故障与独立评估**：只损坏本任务生成的归档副本，固定位置 / 大小 / 种子 / 重复次数。没有恢复能力时明确拒绝，不把检测报错当恢复成功。先在dev确定可比质量点，再登记阈值 / holdout规则；当前不冻结任意多X% / 快Y倍门槛。

固定档测量后事后取出的最佳点只能标作参考包络，不能当作免费在线Oracle。实际时间预算比较中，双方所有试压、调参、选择与最终写出都收费；对手也可在相同预算内选择配置。强静态策略、同算子显式计划与Seed方案分别列出，避免因选择成本归属不同制造优势。

## 当前证据与边界

DEV-019/020只探索固定Zstd-9的29个分组计划，不是多codec速度优化或抗损坏验证。修订5仍拒绝partial / split，不能拿旧v4恢复功能冒充新Seed路径。新分段 / 配置 / 恢复契约须独立设计、版本化和验收，保留旧包可解码，不静默重解释旧种子。现有工具固定Zstd-9，尚未实现本文件的多档固实基准。
