# Seed 与非 Seed 收益拆分：消融实验设计 r1

日期：2026-11-12。设计与首轮可运行组的登记，不冻结协议。输入：[项目评估与发展建议](../../docs/review_results/SeedArc_项目评估与发展建议_2026-11-12.md) 第 5 节 P0-3、第 7 节。前序：[B2-r4 诊断](seed-codec-allocation-r4.md)、[B2-r5 Adaptive-file](seed-adaptive-file-r5.md)、[冻结配置](../configs/adaptive-file-r1.frozen.json)。

## 要回答的问题

在同一份独立数据、同一 64 KiB 分块、同一完整归档计量下，**Seed 本身带来了什么**，有别于“不用 Seed 的内容自适应”？三个可证伪问题：

- Q1：无 Seed 的内容启发式（Adaptive-file-r1）相对固定策略有没有净收益？
- Q2：有 Seed、无搜索（确定性映射）相对固定策略与无 Seed 启发式，是变好还是变差？
- Q3：在相同试编码预算下，有 Seed + 有限预算搜索能否超过无 Seed 启发式？

只有 Q3 为“是”且净收益（扣除 Seed 表示与搜索成本）为正，才能说 Seed 有独立价值。

## 对照组

| 组 | 本仓库对应 | 状态（r1） | 目的 |
| --- | --- | --- | --- |
| G1 固定 Zstd-3 | `zstd3`（Store 回退） | 可运行 | 简单稳定的底线 |
| G2 固定 LZMA2-6 | `lzma6` | 可运行 | 第二个固定参照，避免只比一个基线 |
| G3 无 Seed 内容启发式 | `adaptive-file-r1`（冻结；256 KiB / 1 MiB / 无界） | 可运行 | 纯自适应收益 |
| G4 有 Seed、无搜索 | `b-global`（B-r1，codec_seed=0，Zstd-4，LZMA2-6） | 可运行 | 确定性 Seed 映射的影响 |
| G5 有 Seed、有限预算搜索 | 无实现 | **缺项**，本轮不建搜索器 | 搜索带来的净收益 |
| G6 Oracle | `oracle-file-r1`（每文件全块 × 3 配置） | 可运行，参考上限 | 文件级选择的上界；不是同预算竞争者 |

G4 只有一个 Seed 值（0），它衡量的是“一个确定映射”，不是 Seed 空间的最好值；后者属于 G5。

## 统一计量（每组每数据集）

- 完整归档字节 = 头部 + 索引 + 数据 + **策略所需元数据**。G1–G3、G6 的选择完全由既有逐块 Codec / config 表达，元数据 0 B。G4 / G5 的 Seed 与覆盖字段**尚未序列化**：记为缺项（null），不得记 0；在格式定下前，报告时另给“若用当前 16 B 预留 Seed 字段”的下界敏感性。
- 决策 / 试编码的墙钟与 CPU、最终编码时间、二者合计；解压墙钟与 CPU；压缩与解压进程峰值工作集。
- 候选数、试编码输入字节、预算耗尽文件数；G5 另需搜索步数与“已验证最优结果”保留情况。
- 逐字节往返与同组归档哈希一致。

## 预算对齐（G3 与 G5 的公平比较）

G5 落地时必须与 G3 使用**同一预算单位**（试编码输入字节，r1 的口径），并另报实际 CPU；同时给出预算—大小曲线。G6 不受预算约束，只作为上限，不与 G1 直接比成本。

## 数据与统计

- 只用 [b2r5-corpus-r1](../datasets/b2r5-corpus-r1.json) 的 **test** 划分做结论；dev 划分保留给将来 r2 调参。
- 每组 ≥5 次重复，方案顺序轮换，热缓存（测前通读一次），报告均值 / 中位数 / p10 / p90；逐文件节省分布；负收益与无收益样本单列；按数据类型给“每节省 1 KiB 的额外 CPU”。

## 判定规则（运行前写定）

- 若 G4 在任一类型上比 G1 大，则“无内容依据的 Seed 映射”在该类型为负收益（r4 已在自制样本上观察到）。
- 若 G3 合计不小于 G1，或节省 < 0.1 % 且额外 CPU > 50 %，则视为“无 Seed 自适应在该语料上不划算”。
- Seed 的独立价值只能由 G5 − G3 的净差（含 Seed 元数据与搜索成本）给出；G5 缺失时，**本轮不对 Seed 价值下结论**。

## r1 运行范围

G1、G2、G3（三档）、G4、G6 在 run `20261112-b2-independent-main-001` 中同场运行（见该记录的 ablation 小节）。G5 缺项：未实现受预算搜索器，按要求本轮不新建。

## r2 补充：G5 设计（2026-11-13，DEV-013；只是设计，没有实现）

触发条件已经满足：共享字典在 [b2r5-corpus-r2 的 test 划分](../experiments/20261113-dict-test-main-001/record.md)上有收益。Zstd-9 加一个全局 64 KiB 字典，在三类数据上都比 Fixed LZMA2-6 小，耗时约为它的 0.57 倍。因此 G5 的搜索空间从“逐块 / 逐文件 Codec”改为**分组与字典分配**。

| 组 | 起点 | 候选空间 | 预算 |
| --- | --- | --- | --- |
| G5-direct（无 Seed 的直接搜索） | r1 选出的全局参数（单组，D=64 KiB，训练用全部输入，级别 9） | 分组划分（按目录前缀 / 扩展名 / 大小区间，最多 k 组）× 每组的 D ∈ {16, 64, 112} KiB × T，或者“该组不用字典” | 训练与试编码的输入字节、CPU 时间双口径；固定上限 B |
| G5-seed（结构化 Seed） | 同一起点，编码成 Seed | 同一候选空间；Seed 字段表示分组规则与每组参数，用局部变异（翻转一个字段）生成邻居 | 同一个 B |
| G-dict-r1（基线） | — | 不搜索：单组、全局字典 | 0 |

- **对照要求**：两组搜索的起点、候选集合、预算计量完全一致，都保留“已验证的最优结果”。比较的是同预算下的完整产物字节，以及达到同等字节所需的预算。
- **成本必须计入**：每组一个字典的字节、分组表与组参数的字节，以及 Seed 本身的序列化字节（G5-seed 独有）都算进完整大小，不得记为 0。训练与搜索时间计入压缩时间。
- **归因方式**：G-dict-r1 减去 LZMA2-6，是“字典本身”的收益；G5-direct 减去 G-dict-r1，是“分组 / 多字典搜索”的收益；G5-seed 减去 G5-direct，才是“Seed 的表示与局部变异”带来的额外收益（扣除 Seed 元数据之后）。
- **数据**：只能在 r2 的 dev 划分上开发；评估要用新的、未使用过的留出集（r2 的 test 已经用过一次，不能再拿来调参）。
- 本轮不实现搜索器，也不冻结任何字典或分组格式。
