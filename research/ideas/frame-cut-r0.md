# 有界固实的切点规则（frame-cut-r0）

2026-11-27，DEV-037，主 Agent（Claude）。状态：**测量计划，规则在任何测量之前固定**；不改归档格式，不写归档。用户 2026-11-27 选定此方向（"Study frame cuts"）。

## 动机

DEV-036（[记录](../experiments/20261127-dup-probe-main-001/record.md)）在 dup-local-dev-r1 的"全部"树上发现：同样的内容，只因去掉副本后重新切帧、帧边界整体移动，32 MiB 分帧的帧字节就在 −1.8% 与 +1.6% 之间摆动。现在的切法（`g1-r0`）只看路径顺序和字节上限：一帧装满就切，不看内容。

帧表本来就逐帧记录成员和偏移，解码不依赖切点规则；但同样的输入必须切在同样的位置，被采用的规则以后要进配方 / Seed，标签才真实（ADR-0006 修订属 C 级，本轮不做）。

## 问题

1. **噪声有多大**：只把所有边界平移一点，体积变化的分布是什么？这是判断"某条规则更好"的参照。
2. **简单规则能否稳定胜过这个噪声**：只看路径的规则，以及看内容相似度的规则。

## 规则（本节在测量前固定，测量后不改）

文件按路径顺序排成一列，帧上限为 L。"边界 b"表示帧在第 b 个文件之前结束。

| 名称 | 作用 | 定义 |
| --- | --- | --- |
| `greedy` | 现状（`g1-r0`） | 下一个文件放不下就切。 |
| `shift-k`，k = 1…7 | 噪声参照，**不是候选** | 第一帧上限改为 k·L/8，之后 greedy。 |
| `balanced` | 候选 | n = greedy 的帧数，t = ⌈总字节 / n⌉；当前帧已达 t 或下一个文件放不下时切。 |
| `path-w25`、`path-w50` | 候选（只看路径） | 从帧起点 s 出发，e 为 greedy 能装到的最远边界；剩余文件全装得下时直接收尾。候选边界是 (s, e] 中帧内已累计 ≥ (1−P)·L 的边界，e 总是候选。取相邻两文件公共目录层数最少的边界，相同则取最靠后的。 |
| `sim-w25`、`sim-w50` | 候选（看内容） | 候选同上。每个文件算 128 桶 one-permutation MinHash（8 字节滑动片段，按小端读取，splitmix64 末段混合）。边界左右各取紧邻的文件作上下文，每侧最多 1 MiB、64 个文件，草图逐桶取最小合并。取左右估计 Jaccard 最低的边界，相同则取最靠后的。 |

所有规则都是确定性的，只依赖路径顺序、文件大小和内容，不依赖线程数。

## 方法

- **工具**：`cut-probe DIR VARIANT LIMIT`（[cut_probe.hpp](../tools/cut_probe.hpp)）。
  - 所有规则产生的帧去重后统一压缩，每帧都解回来比对；
  - 输出每条规则的帧数、帧字节总数、每帧 raw 与压缩字节，以及帧 CRC 链。
- **对照**：greedy 的帧字节必须等于 `dup-probe` baseline（同树、同配方、同上限）。
- **数据**：dev 数据，不碰留出集。
  - dup-local-dev-r1 的 cargo / rustup / npm / 全部；
  - append-r1 dev。
- **配方**：Zstd-19 与 LZMA2-9e，32 MiB，与 DEV-036 相同；16 MiB 视时间再加。
- **判定**：
  - 候选规则要在每棵多帧树上都不比 greedy 差；
  - 收益要超过 shift 分布的范围，才算超过噪声；
  - 只在一棵树上好的，记为观察，不当作结论。

## 限制

- 这是探索性 dev 测量，规则一旦按结果挑选，就需要在另外的数据上确认，才能宣称收益。
- 目录层数和 MinHash 都是粗略的代理指标，不保证找到最优切点；最优切点（逐个候选实际压缩）代价太高，本轮不做。
