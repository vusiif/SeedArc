# Seed 设计探索：先验证语义，再选择编码

日期：2026-11-12。状态：**研究计划，未实现、未运行实验、未冻结协议**。

输入：[用户结构化种子草案](../../docs/users_idea/SeedArc_结构化种子设计草案.md)、[项目评估](../../docs/review_results/SeedArc_项目评估与开发建议.md)、[复现要求](../../docs/reproducibility.md)。用户最新决定：Seed 是核心设计，需要亲自比较候选；GUI 按人工测试需要启动，Actions 延后。用户原稿保持不变。

## 1. 问题与边界

研究问题：能否用紧凑、可解释且可搜索的策略表示，在受限计算预算内接近或改善固定算法方案的完整归档体积？暂不宣称独创性或收益；相关工作尚未检索，选型前补齐文献依据。

分别评价：策略表达能力、搜索效率、归档元数据成本。三者可能相互制约，不以“有 Seed”作为收益证据。

当前 M3 头部预留 16 字节 seed，strategy_version 为 0，非空种子会明确拒绝；这只是实验布局，不是已经选定 128 位语义。块表仍保存实际 codec / config，每条 48 字节。第一轮探索不修改持久格式，不删块表字段，不构建通用插件框架。

## 2. 先定义语义层

先用内部命名字段或实验配置描述策略，最后再决定如何压进字节；以下名字是讨论用语，不是公共 API：

- **算法分配**：选择哪些 codec、如何分配到块。候选集合与排序由实验版本固定，不取决于本机装了哪些库。
- **参数控制**：分别控制 Zstd / LZMA2 的合法等级；参数字段变化不应无声明地改变算法分配。
- **变化范围**：明确控制全归档、一个文件、连续块段或指定子集。先验证是否值得加入，不提前分配固定比特。
- **分块 / 分组**：第一轮仍固定分块、块间独立。后续候选单独研究，明确改变边界会使块身份、输入与缓存依赖变化。

复现条件写为 `Plan = G(candidate_version, semantic_seed, canonical_block_metadata)`。每个候选必须定义合法输入、块身份和编号、整数运算、映射规则及测试向量；同一候选内可复现，不要求不同候选输出一致。实验配置版本不得自动变成正式归档策略版本。

## 3. 比较三个小型候选

| 候选 | 设计 | 检验目的 / 局限 |
| --- | --- | --- |
| A：非结构化随机映射 | 整个种子驱动算法及参数的确定性随机调度 | 简单对照；不保证字段隔离或局部性 |
| B：字段分离 | 算法字段与各 codec 参数字段分别映射，使用独立的确定性输入域 | 检验可解释性和坐标搜索；字段分离不等于只改变一个块 |
| C：字段分离加作用范围 | 在 B 上显式限制一次变更作用的文件 / 块段 | 检验局部搜索潜力；可能增加编码成本、限制可表达策略 |

优先 A 与 B；只有比较发现局部变化粒度确有不足再原型 C。候选先支持相同的 codec / 等级范围、固定块输入，避免同时改变表示和压缩能力。参数邻近值可尝试直接或分层映射，算法随机化可使用独立确定性混合；具体 PRNG、域区分方法、位宽和编码均未选定。

短种子不能无损表示任意逐块计划：b 位最多区分 2^b 种种子。必须量化有效计划数量、重复映射和未覆盖的策略，避免把位数多或随机性强当作表达力好。

## 4. 块身份与解码契约的待选问题

- 全局块序号简单，但前面插入文件会改变后续编号；文件相对标识加文件内块序号可能隔离这种影响，但引入路径规范化及重命名语义。先用插入、重排、重命名测试比较，不承诺一种做法天然更好。
- 生成过程应能说明随机访问某块与顺序生成是否一致；若采用有状态 PRNG，明确遍历和跳过规则，不能因实现顺序改变计划。
- Store 回退依赖原文试压，实际选择必须记录。拟议计划与实际使用 codec 分开输出。
- 第一轮仍以实际块描述解码。Seed 是否仅记录编码策略，还是未来省略部分描述并参与解码，属于不同实验；后者须独立评估错误路径、收益和兼容性，不能顺手删除字段。
- 未实现字段的规则须按候选版本明确为拒绝、保留零值或有定义的无作用；不在版本间悄悄赋予旧值新含义。

## 5. 可证伪假设与评价

| 假设 | 检查 | 失败 / 无收益条件 |
| --- | --- | --- |
| B 能隔离字段职责 | 固定输入与其他字段，只改参数字段，比较每块 codec 和参数 | codec 或分块发生未声明变化 |
| 有序参数映射便于微调 | 记录参数相邻输入的等级变化、改动块占比 | 大量跳变或大量重复计划；不能仅凭参数平滑推导体积平滑 |
| B / C 比 A 更容易搜索 | 相同数据、候选能力、预算，比较随机与字段局部搜索 | 重复运行无稳定收益或成本更高 |
| 紧凑表示有实际价值 | 统计实际归档总长、所有元数据及表示不同的成本 | 仅增加种子而块表不变，不能宣称节省索引 |

对每次变更保存可人工阅读的计划差异：块身份、拟选 codec / level、实际 codec、影响原因。先用 CLI / JSON 与静态报告提供给用户比较；当这些不足以完成交互测试时，再安排轻量 GUI，不用先建设完整产品界面。

## 6. 基线与预算

- 固定参数 Store、Zstd、LZMA2；简单无 Seed 策略必须写出具体规则。
- 同一有限 codec / 参数集合的逐块试压择优，计入每次编码和实际索引成本。固定分块、独立块、固定元数据成本且不限制计算时，它给出该候选集合内的体积下界，Seed 调度不能靠重新排列相同选择突破此下界。
- Seed 的有限预算随机搜索、字段局部搜索。比较搜索方法时限制相同资源预算；固定算法保留真实耗时，不人为运行到预算用尽。
- 同时报每块试压次数、实际编码工作量、总时间、内存、完整归档大小、重复计划比例与最优候选轨迹。候选次数相同不代表编码工作相同；将来缓存必须计入开销。
- A / B 无收益也是结果。跨块字典、分组或改变边界可能改变优化问题，留到独立实验，不为获得正结果混入第一轮。

## 7. 实施与用户评估顺序

1. 建立 M3 固定算法 Release 基线与固定输入清单，保留可再生成命令；先保存旧格式小样例。
2. 为 A / B 写候选规则与向量，用小型内部原型输出可比较的块计划；不修改归档格式。
3. 请用户比较字段含义、编辑动作与计划变化是否符合预期。用户评估是设计关口，不能由“测试全绿”替代。
4. 用小规模探索比较表示与搜索行为。每个候选冻结该次运行的配置；使用不同实验版本迭代，保留负面结果。调参数据与独立评估数据分开。
5. 选择可解释、可验证的实验方案后写 ADR，决定种子编码、受支持策略和归档接入。选中一个原型不等于冻结长期协议；格式兼容重大取舍按项目权限模型确认。
6. 再进入完整往返、跨工具链向量、动态分析、负测和 MVP 验收；M5 扩展预算搜索。

所有实验使用现有 datasets / configs / experiments / results / scripts 结构。每次实际运行记录代码版本与差异、环境、输入哈希、完整命令、配置、原始结果和限制。本文件没有 run ID 或实测结论；未来在此链接对应实验。Actions 延后，当前通过本地检查保留质量证据。

## 8. 为后续修改保留的实现边界

用户明确要求：探索最佳种子方案是持续开发内容，M4 选型之后也要方便修改。以下是未来实现约束，当前尚未实现。

- **分开表示与映射**。种子的文本 / 字节编码、语义字段解释、字段到策略的映射分别处理。压缩管线只接收经过校验的具体块计划，不解析种子位段；CLI / GUI 不各自复制映射逻辑。更换布局或映射应集中在 seed 模块及对应测试。
- **候选身份显式化**。实验记录使用候选 ID 与规则修订号，不能只保存一个裸种子数值。进入归档时区分容器版本、种子表示版本与策略映射版本的职责；是否分字段编码由 ADR 决定，不提前新增头部字段。相同版本下不得悄悄改变含义。
- **长度可演进，但始终有界**。探索接口不把固定 16 字节散布到核心、UI 和研究脚本；每种候选明确自身长度、字段约束与资源上限，不意味着立即实现无限长 seed 或通用 TLV 系统。将来超过当前头部容量时，走明确的实验格式演进，不能借用保留字节暗改语义。
- **保留具体执行结果**。初期归档继续保存实际块 codec / config，Seed 记录编码策略；新方案的探索不要求重写解压管线。将来让 Seed 替代部分描述时，单独审查其解码依赖与兼容成本。未知必需版本明确拒绝，不静默按最新映射解读。
- **旧实验可复现，旧数据可恢复**。修改候选语义时记录新修订，保留旧代码版本、配置与固定向量。实验脚本通过版本选择候选；无需把所有淘汰候选永久留在生产库中。若解码依赖某版本映射，承诺支持的归档必须保留相应解码能力或经授权迁移，不能仅靠 Git 历史代替可解码保证。不同布局之间不存在默认无损种子转换。
- **最小替换机制**。先用少量显式分派和独立函数比较真实候选，配套边界与版本测试；不预建动态插件、脚本运行时、万能配置框架或完整迁移平台。实验成熟再扩展共同接口。

未来验证替换成本：在不改变现有候选输出的前提下添加另一种布局 / 映射，检查改动是否集中于 seed 模块、候选配置与测试；现有 codec、I/O 和解压实现不应因位段调整而跟着修改。研究脚本按候选版本解释输入，不把一种布局写死为全项目默认。

**阶段验收表示某个实验版本可用，不表示种子设计探索结束；长期外部兼容承诺另行确认。**
