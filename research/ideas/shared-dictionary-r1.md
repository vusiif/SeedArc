# 跨文件共享字典可行性 r1（阶段 D 第一步）

日期：2026-11-13。DEV-013。运行前登记，不冻结任何格式。前序：[DEV-012 独立评估](../experiments/20261112-b2-independent-main-001/record.md)（Oracle 只比 Fixed LZMA2-6 小 10,927 B / 0.025 %，已复核）、[seed-ablation-r1](seed-ablation-r1.md)。语料：[b2r5-corpus-r2](../datasets/b2r5-corpus-r2.md)（按分组划分，dev / test 内容哈希不相交）。

## 问题与假设

在固定 64 KiB 分块、逐块独立编码的前提下，逐文件选 Codec 的空间已基本用尽。剩下的问题是：在同一归档里共享一个训练好的 zstd 字典，能否利用**跨文件重复**的内容，在把**字典与分组索引都计入成本**之后，得到净收益？

- H1（大小）：同级别 Zstd 下，带字典的完整容器在三类数据上**都**小于无字典容器。
- H2（与 LZMA2-6 的取舍）：带字典的 Zstd 要么在相近总耗时下比 Fixed LZMA2-6 更小，要么在相近体积下明显更快。

## 方案

| 方案 | 实现 | 说明 |
| --- | --- | --- |
| P-zstd3 / P-lzma6 | 生产归档（`seedarc_seed_archive` 的 zstd3 / lzma6 模式） | 参照组。耗时包含生产路径的自校验和安全提交 |
| C-nodict-L | 研究容器，无字典，Zstd 级别 L | 与字典组同一容器、同一开销，用来隔离字典本身的效果 |
| C-dict-L(D, T) | 研究容器，字典 D 字节，训练输入预算 T | 主研究对象 |

- **级别**：L ∈ {3, 9}。3 是用户要求的基线。加 9 的理由：字典带来的增益在高一些的级别上通常仍然存在，而 Zstd-9 的耗时介于 Zstd-3 和 LZMA2-6 之间，可以检验“在相近耗时下与 LZMA2-6 比体积”这一判据。
- **字典大小**：D ∈ {16 KiB, 64 KiB, 112 KiB（zstd 默认）, 256 KiB}。
- **训练预算**：T ∈ {1 MiB, 4 MiB, 全部输入}。训练样本取每个文件的第一块（最多 64 KiB），按路径的 FNV-1a 哈希排序依次选入，直到用完预算。
- 字典在压缩时用**本次输入本身**训练，并存进容器，因此训练时间计入压缩耗时、字典字节计入容器大小。dev 划分只用来**选 D 和 T**，不用来训练测试时使用的字典。

## 研究容器（实验用，不是归档格式）

结构：头部 32 B、字典、分组表（每个文件 1 B，标明是否使用字典）、索引（每个文件：路径、大小、块数；每个块：存储长度、类型、CRC32C）、数据区。报告中逐项列出各部分字节，全部计入完整大小。解析有上限：字典不超过 1 MiB、文件数、路径长度、块数与大小一致、各部分总长与文件长度严格一致；解码只写到内存，再与原文件比较。

## 选参规则（只用 dev）

对每个级别 L，在 (D, T) 网格中选**三个 dev 数据池的完整容器字节之和**最小的一组；平手时取较小的 D，再取较小的 T。选定后写进 run 记录，然后在 test 上**只做一次**正式评估。如果需要重跑，记录原因。

## 判定（运行前写定，用户给定标准的操作化）

- H1 成立：test 三类数据上，C-dict-L 都小于 C-nodict-L，且总压缩墙钟（读入 + 训练 + 编码）不超过 C-nodict-L 的 1.5 倍。
- H2 成立，以下二者满足其一：
  - (a) 相近耗时更小：C-dict-L 的总压缩墙钟不超过 P-lzma6 的 1.25 倍，且三类数据上都比 P-lzma6 小；
  - (b) 相近体积明显更快：三类数据上都与 P-lzma6 相差不超过 ±2 %，且总压缩墙钟不超过 P-lzma6 的 0.5 倍。
- 达不到就记为**无收益**。另外报告：分位数（逐文件存储字节相对无字典的变化）、按类型的结果、负收益文件、单文件提取耗时（含读容器、解析索引、加载字典）。

## 接口改动的 B 级评估

- **新增**：`core/codec/dictionary.{hpp,cpp}`（命名空间 `codec::research`）以及独立的研究目标 `seedarc_codec_dictionary`。zstd / zdict 头文件仍然只出现在 `core/codec/` 内。
- **影响**：生产库 libseedarc、公共 API、归档格式、生产解码器都没有改变，也不依赖这个目标。
- **资源边界**：
  - 字典大小限定在 256 B 到 1 MiB；训练输入不超过 64 MiB、样本不超过 2^20 个。
  - 解码时要求帧的字典 ID 与所用字典一致；只接受恰好一个帧；内容大小必须精确相等；声明的窗口不得超过“字典 + 块”的大小。
  - 窗口上限是在生产规则“不超过块大小”的基础上加上字典大小。这个上限反映的是单次解码真实需要的内存，没有放松生产路径的检查。
- **回滚**：删除这个目标及其测试和工具即可，不影响生产代码。
- **测试**：`codec.dictionary_research`，覆盖往返、收益、错误字典、无字典帧、尾随字节、截断、大小不符、容量上下限、过大字典、非字典内容、非法级别。

## 后续（本轮不做）

- **固实压缩**：对同组文件做连续流压缩，比逐块独立编码更能利用跨文件重复，但会牺牲随机访问，需要另行设计索引。
- **G5**：只有当本轮的简单分组加共享字典确实有收益时，才在 seed-ablation 里补充 G5 的设计（见下节）。

## G5 设计补充（有条件）

见 run 记录的结论。如果字典有收益，G5 定义为：结构化 Seed 决定**分组方式与字典分配**（例如按目录或类型分成 k 组、每组一个字典、各组的 D / T），与**直接搜索**同一参数空间的方法对照。两者使用相同的起点（r1 选出的全局参数）、相同的候选范围、相同的试编码 / 训练预算（按字节和 CPU 时间双口径计量），才能分清收益有多少来自字典本身、多少来自 Seed 的表示与局部变异。分组与字典的元数据都要计入。本轮只写设计，不实现搜索器。

## 结果（2026-11-13）

- dev 调参：[20261113-dict-dev-main-002](../experiments/20261113-dict-dev-main-002/record.md)，两个级别都选 D=64 KiB、训练用全部输入。
- test 正式评估（唯一一次）：[20261113-dict-test-main-001](../experiments/20261113-dict-test-main-001/record.md)。
  - **H1 不成立**：字典在三类数据上都让容器变小（Zstd-3 −4.2 % 到 −21.4 %，Zstd-9 −7.8 % 到 −24.8 %），但训练使总耗时变成无字典的 1.45–3.3 倍，超过 1.5 倍上限。
  - **H2(a) 对 Zstd-9 成立**：三类数据上都比 Fixed LZMA2-6 小（−4.7 % 到 −29.4 %），耗时约为它的 0.57 倍；按生产格式的索引大小折算后，合计仍小 12.1 %。Zstd-3 带字典在 source 上比 LZMA2-6 大，不成立。
- G5 的条件设计已补进 [seed-ablation-r1](seed-ablation-r1.md#r2-补充g5-设计2026-11-13dev-013只是设计没有实现)。固实压缩仍是后续项。
