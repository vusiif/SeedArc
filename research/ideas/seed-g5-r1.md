# G5：带预算搜索的结构化 Seed（r1 计划）

状态：**已实现，dev 探索运行一次（探索性），配置尚未冻结，留出集尚未使用**。日期：2026-11-14。任务：DEV-016。来源：[seed-ablation-r1 的 r2 补充](seed-ablation-r1.md#r2-补充g5-设计2026-11-13dev-013只是设计没有实现)、[shared-dictionary-r1](shared-dictionary-r1.md)、用户想法 [结构化种子草案](../../docs/users_idea/SeedArc_结构化种子设计草案.md)（已读快照未变化，SHA256 `368AD5B9…`）。用户 2026-11-14 选定留出集用“本机 + 公开”混合语料，并同意下载 Django 6.1.3 源码包。

## 1. 要回答的问题

只回答 Q3：**在同一份预算下，结构化 Seed 加局部变异，能否在“分组与字典分配”上胜过不用 Seed 的直接搜索？** 只有扣除 Seed 元数据和搜索成本之后净收益仍为正，才能说 Seed 有独立价值。

| 组 | 做法 | 用途 |
| --- | --- | --- |
| LZMA2-6 | 固定 LZMA2-6，逐块，不用字典 | 外部参照 |
| G-dict-r1 | 单组、全局 64 KiB 字典、Zstd-9、训练用全部输入（DEV-013 选出的参数），不搜索 | 起点和基线，预算 0 |
| G5-random | 在候选空间内均匀随机采样，保留已验证的最好结果 | 直接搜索（弱） |
| G5-coord | 直接在参数上做坐标搜索：每次改一个参数，接受改进 | 直接搜索（强），是 G5-seed 的主要对照 |
| G5-seed | 参数编码成结构化 Seed；邻居 = 翻转一个字段；爬山 + 固定次数重启 | 被检验对象 |

三种搜索使用**同一个起点（G-dict-r1）、同一个候选空间、同一个评估器和同一个预算计量**，评估结果都做缓存。G5-seed 和 G5-coord 唯一的区别是邻居怎么生成、怎么编码，这样 G5-seed 减 G5-coord 才能归因到 Seed 的表示本身。

## 2. 候选空间（r1，暂定，在 r2 dev 上确定后冻结为 g5-r1 配置）

- **分组规则**：按目录前缀（深度 1 或 2）、扩展名、大小区间（≤ 1 KiB / ≤ 16 KiB / 更大）三选一；组数上限 k ≤ 8，超出的小组并入“其他”组。
- **每组参数**：字典大小 D ∈ {不用字典, 16, 64, 112} KiB；训练样本 T ∈ {全部, 每文件前 4 KiB}；Zstd 等级固定 9（沿用 DEV-013）。
- **Seed 编码**（只给 G5-seed 用；位宽不冻结，见 AGENTS.md 第 6 节）：规则（2 位）+ 规则参数（2 位）+ k（3 位）+ 每组 D（2 位）和 T（1 位）。按 k = 8 计算最多 31 位，序列化为 4 字节。完整大小同时报“按 4 字节计”和“按现行 16 字节预留计”两个口径。

## 3. 预算与计量

- **主预算单位**：训练和试编码读入的输入字节数（与 G3 的 r1 口径一致），上限 B ∈ {2, 4, 8} × 语料字节，给出预算—大小曲线。另报实际 CPU 时间和墙钟时间。
- **停止条件**：预算用完，或连续 N = 20 次评估没有改进（N 在 dev 上确定后冻结）。
- **随机性**：随机采样和重启用 SplitMix64（`third_party/splitmix64`）。每组跑 5 个搜索种子，报最小值、中位数和最大值；没有固定随机种子就不能出结论。
- **完整大小**必须计入：容器头和索引、每组字典字节、分组表、每组参数，以及 G5-seed 的 Seed 字节。不得记 0。

## 4. 指标

每次运行都记录：完整容器字节；各部分字节（数据 / 字典 / 元数据）；压缩、训练和搜索时间；解压全部文件的时间和单文件解压时间；峰值内存及测量口径；评估次数和缓存命中数；已验证最好结果的出现位置；逐字节往返结果。原始数据存 JSON，汇总由脚本生成。

## 6. 可证伪的假设（在 dev 上冻结参数之后才看留出集）

- **H1**：在预算 B = 4× 时，G5-coord 的完整大小比 G-dict-r1 至少小 1 %，至少在两个数据池上成立。
- **H2（Seed 的独立价值）**：同一预算下，G5-seed 五个种子的中位数比 G5-coord 的中位数小（已计入 Seed 字节）；或者达到 G5-coord 最好结果所需的预算更少。两个数据池以上不成立，就判定**本轮没有发现 Seed 的独立价值**，照实记录这个负面结果。
- **H0（必须满足）**：所有产物逐字节往返；同一配置、同一种子重跑，得到的字节完全相同。

## 7. 实现边界

- 只扩展研究工具 `research/tools/dict_study.cpp` 和研究容器，不改生产归档格式，也不冻结任何分组或字典格式（字典进生产属 C 级，等 G5 和固实对照的结论出来再写 ADR）。
- 管线只接收具体的分组与字典计划，Seed 的解释集中在一个映射函数里（AGENTS.md 第 6 节）。
- **运行位置**：开发和小规模调参在本机。留出集上的搜索可以放到印度服务器上，用 `in-long-task` 在资源上限内运行（shared 模式最多 2 核、3 GiB），只用于借算力，不对服务器本身做压力测试。各机器的耗时分别报告，不混在一起比较。

## 7.1 实现（2026-11-14）

- **工具**：`research/tools/g5_study.cpp`（`seedarc_g5_study`），使用研究容器 v2（魔数 `SADXR002`）：
  - 头部 40 字节；
  - 可选的 4 字节 Seed（只有 seed 方法写入）；
  - 组表：每组记录字典大小和字典的 CRC32C，共 8 字节；
  - 各组字典；
  - 每个文件 1 字节组号；
  - 索引和数据，格式同 v1。
- **Seed 可校验**：分组只依赖路径和大小，所以解码端能从索引重新算出分组。容器带 Seed 时，解析会核对 Seed 与组表是否一致，因此 Seed 本身也有完整性检查。
- **三种搜索**共用一个按组缓存的评估器；预算只计未命中缓存的训练字节和试编码字节。
- **结果可信度**：最终计划会重建一遍，断言重建大小等于评估时的大小，再在内存里逐字节往返。
- **交叉核对**：起点计划与 `dict_study pack 9 65536 0` 的字典和数据完全一致，容器只多出 v2 头和组表的 12 字节。
- **测试**：CTest `research.g5_study`（`check_g5.cmake`，只在 `SEEDARC_BUILD_RESEARCH_TOOLS=ON` 时注册），覆盖：
  - 同一个种子产物逐字节相同；
  - 三种方法都能往返；
  - 只有 seed 方法的产物带 Seed；
  - 拒绝覆盖已有输出、拒绝非规范计划、预算不足时干净失败；
  - `selftest`：116 个损坏或截断的容器全部被拒，10,000 个 Seed 编码解码往返。
  - 通过的配置：MSVC Release、GCC UCRT64 Release、Linux GCC Release、Linux Clang ASan+UBSan。
- **运行脚本**：`research/scripts/g5_run.py`。`--phase holdout` 必须同时给出冻结配置，并且方法、预算、种子和 stall 都要与之一致，否则拒绝运行。

## 7.2 dev 探索的发现（[20261114-g5-dev-main-001](../experiments/20261114-g5-dev-main-001/record.md)，探索性）

- 按组缓存让搜索空间到 32× 预算时就被基本穷举，三种方法收敛到同一个计划。这对 Seed 本身不利：同一个空间里，表示方式的差别只在小预算下才可能体现。
- 收益很小（r2 dev：0 到 −2.6 %），最大的单项来自训练样本只取前 4 KiB，而不是分组本身。
- 因此正式配置的候选预算改为 {2, 4, 8, 16}×，每格 5 个种子。还要在 dev 上再跑一轮确认，才冻结。
