# SeedArc 种子映射、确定性与复现范围

> 设计目标不是不计条件地承诺“相同 seed 永远相同字节”；必须明确复现前提、版本和测量方法。本文没有替项目预选 PRNG 或种子宽度。

## 1. 数学模型

给定文件集合 `F`、种子 `S`、策略生成器版本 `V` 和解码侧可以获得的规范化元数据 `M`：

```text
P = G(S, V, M)
A = Encode(F, P, codec_versions, archive_format, metadata_policy)
```

- `S` 是策略输入，**不是**原始文件内容或可靠密钥。
- `M` 必须由解码器可获得或从归档恢复；不能悄悄依赖原始文件的数据统计量。
- 如某候选策略按原文试压后选出算法，则把该不可重建的决策最小化地记录到归档索引。
- 保留必要的块长度、偏移、字典、压缩选项 / 标识等解码信息，不以“种子可推导”为由省略必须数据。

## 2. 固定并版本化的内容

1. **种子表达**：宽度、序列化字节序、文本输入、无效输入、外置 / 内嵌模式。
2. **伪随机数生成器**：精确定义算法、状态初始化、输出顺序、版本和固定测试向量；严禁依赖 `std::uniform_int_distribution` 等实现相关序列。
3. **均匀映射**：确定性地将 PRNG 输出映射到分块长度、编码器 ID、等级等离散空间；若要无偏映射，应规定拒绝采样及重试消耗字节规则。
4. **文件清单**：目录遍历、相对路径、路径分隔符、Unicode、大小写冲突、重复条目、文件顺序、空目录及特殊对象的处理。
5. **元数据**：时间戳、权限、操作系统字段、文件顺序和元数据序列化的可复现政策。
6. **编码器**：算法 ID、库版本、参数、窗口 / 字典、并行模式和运行时功能检测；版本差异可能改变压缩比特流。
7. **写入顺序**：工作线程完成顺序不可影响索引 / 块在归档里的顺序；压缩输出应按规范顺序提交。
8. **二进制布局**：固定字段字节序、整数编码、哈希算法与可选字段排序。

## 3. 三层不同的复现承诺

| 层次 | 目标 | 验证 |
| --- | --- | --- |
| **策略复现** | 相同种子、生成器版本和解码可用元数据 → 相同策略 | 固定 seed→参数测试向量，跨已支持编译器比对 |
| **同环境归档复现** | 规范化输入、元数据政策、压缩库 / 构建、格式与线程写出规则固定 → 逐字节相同归档 | 多次完整归档哈希对比，含并发变化测试（按契约） |
| **旧版解码兼容** | 新解码器能还原明确支持的旧归档 | 旧版 golden fixtures，跨版本往返 / 校验 |

这三项不能互相替代。**跨编码器版本逐字节一致**属于额外验证目标，不是默认保证；跨 MSVC / GCC / Clang 的具体保证也必须写进契约并实际测试。

## 4. 测试与诊断

- 固定一批短测试种子（如零、最大值、重复字节、边界值）以及 seed→PRNG 输出→策略参数的**规范测试向量**；正式数值须随 PRNG ADR 一起确认。
- 固定输入快照，并记录标准化路径列表、文件内容哈希、文件元数据政策、格式版本、库版本及工具链。
- 至少对同一输入 + 同一 seed 重复压缩，逐字节对比归档；如支持可变线程数，测试不同线程数的写出顺序。
- 出现不一致时分别比较：清单、策略参数、每块输出、元数据索引、归档尾部 / 校验；避免直接称“seed 不确定”。
- 搜索可使用多个不同 seed 探索，但每个 seed 的策略映射仍需可复现。缓存键必须覆盖所有影响输出的输入与依赖因素。

## 5. 修改权限

- PRNG / 映射尚未冻结时，Agent 可以做带测试的候选实现与微基准，说明实验身份和缺失的承诺。
- 种子协议 / 归档格式发布或有持久数据后，变更映射、版本语义、文件规范化结果或解码条件属于**兼容性变更，必须事前确认**。
- 不能以平台差异、随机库差异或新增多线程为由无声明破坏已明确承诺的复现行为。

## 6. 实验种子的可演进性

种子设计允许在 M4 以及后续开发中继续探索。分离种子表示、语义解释和策略映射，核心压缩管线接收具体计划；不将候选位宽或位段解释散布到 codec、I/O、CLI / GUI。具体候选与替换成本验证见 [Seed 设计探索](../research/ideas/seed-design-study.md#8-为后续修改保留的实现边界)。

实验记录绑定候选 ID、规则修订、配置与代码版本；变更语义生成新修订，旧向量不随新规则覆盖。区分容器、种子表示与策略映射的版本职责，实际线格式由 ADR 决定；当前 16 字节预留不冻结未来设计。未知必需版本明确失败，所有长度与资源开销仍有界。

初期归档保留实际块描述，允许编码策略迭代而不要求解码器重放新映射。若未来解码依赖 Seed，则承诺支持的旧版本必须保持可解码，不能只留下代码仓库历史。淘汰的纯实验候选可由固定代码版本及记录复现，无需永久进入生产分派。阶段验收不自动升级为长期协议冻结。
