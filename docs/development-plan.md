## 首版范围

MVP 支持普通文件和目录、固定分块、Store / Zstd / LZMA2、内嵌种子，以及规划中的 compress / extract / verify。
先单线程，默认拒绝覆盖，明确拒绝未支持的链接、重解析点和特殊文件。
外置种子、搜索、更多算法、插件、加密、固实压缩和共享字典后置。轻量 Qt GUI 按用户交互测试需要启动，不绑定 M4 完成时间；搜索界面按核心实际能力补齐。Actions 延后，不作为当前推进前提。

先用 Store 验证容器和恢复，再接入编码器，最后引入种子映射。安全检查与功能一起交付，失败不得留下伪装成功的结果。

## M0：工程骨架

- 核对实际 CMake、CTest 与编译器，优先建立 MSVC x64 主链路；GCC / Clang UCRT64 使用独立构建目录逐步验证。
- 建立 CMakeLists.txt、CMakePresets.json 和最小 core / cli / tests；目标为 libseedarc / seedarc_cli，CLI 输出名 seedarc。
- C++23、目标级警告、MSVC /Zc:__cplusplus；可恢复错误类型、checked arithmetic，首批采用小型 CTest 驱动。
- CLI 先提供帮助、版本和参数错误，未实现命令明确失败。

验收：主链路 Debug / Release 编译、链接、执行与 CTest 通过，共享配置无用户绝对路径。此时不宣称压缩可用。

## M1：实验格式与安全 I/O

- 提出 ADR：魔数、版本、字节序、算法 ID、索引 / 块关系、空条目、校验覆盖与未知字段处理。
- 规定输入排序、路径编码、Unicode / 大小写冲突、元数据规范化及读取期间文件变化的处理。
- 给出单块、索引、文件数、路径、总输出、字典及累计内存的候选上限；具体值经原型测量。
- 验证 Windows 句柄级创建、不跟随重解析点、安全临时写入、无覆盖提交与失败清理，不能只依赖字符串前缀或 canonical 检查。
- 选择完整性校验算法及依赖，不将普通校验当作恶意篡改认证。

验收：字节级向量、溢出 / 截断 / 未知字段 / 路径负测与安全写入原型通过。格式标记 experimental，外部冻结前单独确认。

## M2：Store 端到端闭环

- 有界读取、固定分块、Store、实验容器读写；先单文件，再目录、空目录和多文件。
- 实现三个基础 CLI 命令，verify 共用受限解析与解码路径，无需恢复用户文件。
- 临时写入、校验、安全提交和失败清理形成完整流程；防止输出再次被枚举成输入。
- 安全恢复同时检查磁盘既有路径，不能只验证归档内名称。

验收：空文件 / 目录、单 / 多块、嵌套目录、非 ASCII 名称、大量小文件、高熵数据逐字节往返；损坏包、超限、路径攻击、覆盖冲突、受控 I/O 失败负测通过，验证有界内存。

## M3：Zstd 与 LZMA2

- 核对真实 vcpkg port、CMake target、baseline、triplet、许可证和 ABI，建立 manifest，逐个接入并验证。
- 需随仓库保存的外部源码按 [third_party 规范](../third_party/README.md) 归档，包缓存不复制入库，项目适配器仍位于 core/codec。
- C API 限于 core/codec，以 RAII 管理资源；受限缓冲 / 流式处理，检查返回值、输入消耗、输出长度和字典内存。
- LZMA2 优先评估 liblzma，明确原始流 / 容器选择及必需解码参数，此处仅为候选。
- 若加入 Store 回退，比较完整块记录成本，记录实际编码选择。

验收：三种算法往返、截断 / 畸形输入 / 参数 / 资源边界测试通过；依赖可追溯，执行所选工具链实际支持的动态分析并说明覆盖范围。

## M4：种子设计探索、确定性与 MVP 验收

先验证种子设计，再选择实验协议；位宽、字段划分、PRNG 与映射不提前冻结。种子表示与映射保留独立替换边界，选型后仍可继续探索；阶段验收不等于长期冻结。具体候选、假设和评估步骤见 [Seed 设计探索](../research/ideas/seed-design-study.md)。

- **M4-A：候选与设计验证**。记录 M3 Release 单算法基线；以非结构化映射为对照，比较语义字段分离、参数局部性与块身份方案。先输出可比较的块计划，不改归档格式。128 位预留不作为最终语义承诺。Actions 延后。
- **M4-B：用户评估与实验选型**。通过 CLI / JSON / 报告让用户比较编辑种子后的真实影响；需要交互时再启动 GUI。小规模试验记录重复映射、变化范围、预算与完整归档成本，不预设收益。选中方案后写实验 ADR 与固定向量；不自动冻结长期格式。
- **M4-C：归档接入与验收**。将选定实验方案接入；受限参数、实际 Store 回退、未知版本拒绝、解码信息完整、旧样例回归；验证完整往返、同环境归档复现与跨已支持工具链策略向量。运行适用动态分析与 Fuzz，说明覆盖范围。

验收：用户完成种子语义评估；候选比较和选择理由有据可查，实际实验按 research 规范归档；此前回归、seed 向量、归档确定性、安全负测及失败清理通过。M4-A / B 允许迭代，不要求先定协议再测试。对外冻结另行确认，保留 golden archives；不以获得压缩率正收益作为功能验收前提。

## UI-1：按人工交互测试需要启动的轻量 Qt GUI

- 启动条件是用户需要交互测试，CLI / JSON / 报告不足以有效比较；可随种子探索需要安排，也可延后，不自动在 M4 后开工。
- 按实际测试需要复用核心库，逐步提供种子计划比较、文件 / 目录选择、压缩、解压、校验、进度和清晰错误提示。
- 耗时操作不阻塞界面；进度 / 取消按核心实际接口实现，不显示伪进度或假成功。核心保持无 Qt 依赖。
- 核对 Qt 与核心工具链 ABI，GUI 作为独立可选构建目标，不阻塞 CLI 构建。

验收：GUI 驱动的逐字节往返与校验、输出冲突 / 损坏包错误显示、任务期间界面响应；如提供取消，必须验证失败清理。界面范围按实际测试任务裁剪，不要求等待搜索研究完成。

## M5：公平基准与有限预算搜索

- 先建立基准，再做单线程随机搜索、次数 / 时间 / 内存预算与取消。
- 对照单算法固定等级、包含选择元数据的逐块择优与随机种子搜索，输入相同、计算预算可比。
- 记录完整归档字节数、编码 / 搜索 / 解码时间、峰值内存、候选数、种子、环境与往返结果。
- 保留已验证最优候选，无收益如实报告，取消与失败不能破坏既有最优产物。
- 基线稳定后逐个评估 Brotli、DEFLATE、LZ4；缓存与并发只在测量证明瓶颈后加入。

验收：Release 实验可复现；预算终止、取消收尾、最优候选保留测试通过，报告完整搜索成本，不预设优于逐块择优。

UI-2：M5 核心搜索验收后，补预算设置、搜索曲线和结果对比；曲线来自实际运行指标，复用核心预算与取消机制。

## M6：研究与产品化

按基准数据在内容定义分块、聚类、固实压缩和字典中逐项实验，量化净收益再扩展。GUI 产品化完善、认证加密、插件、安装包分别安排后续任务。
公开发布前完成威胁模型、持续 Fuzz、依赖安全 / 许可审查、兼容样例与发布目标测试。

## 决策与下一步

许可证已授权；主工具链在 M0 核验；容器 / 校验 / 路径 / 限额在 M1 提出 ADR；依赖与 LZMA2 流在 M3 决定；PRNG、种子宽度、复现范围在 M4 验证。对外冻结须明确确认，不能将原型自动升级为长期承诺。

目录安全恢复与资源边界是关键风险，不能推迟到发布前补齐。种子收益是研究问题，不要求必须得到正结果。目前缺少吞吐实测与执行资源依据，以里程碑推进，不给出无依据的日历工期。
