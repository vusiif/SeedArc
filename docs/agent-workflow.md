# SeedArc Agent 执行流程、权限细则与变更审计

> 根目录 `AGENTS.md` 是日常快速决策入口；本文是复杂任务和有争议决策时的执行细则。目标是**多做有证据的自主工作，少做无必要的确认**。

## 1. 三级权限具体示例

| 类别 | 可做什么 | 需要怎样处理 |
| --- | --- | --- |
| **A 自主** | 局部实现 / 私有数据结构、错误消息、模块内重构、补单元和负测、普通 CMake target 参数、注释和文档、修普通构建问题 | 在任务范围内直接完成并验证；在交付中记录变更，不必为每个实现细节请示 |
| **B 评估影响** | 新压缩库 / 测试依赖、公开 API 增量、默认线程 / 分块大小、缓存策略、局部并行架构、性能策略切换 | 先说明行为、ABI / 许可 / 性能影响及回退方案；**不改变已承诺外部契约、无需系统权限、属于授权任务且可验证**的可自主实施，其他情况先确认 |
| **C 事前确认** | 删除 / 覆盖用户数据，`git reset --hard` / `git clean -fdx` / 强推，系统 PATH / 注册表 / 管理员安装，关闭安全限制，改变冻结归档 / 种子协议，废弃旧格式、变更对外许可 | **不得先执行再解释**。提出备选、风险、验证 / 回滚并等待明确许可 |

特殊规则：**实际影响优先于操作名字**。例如“只是改一个默认常量”，若改变已发布归档字节含义，应升级 C；“新增一个私有辅助结构”，即使涉及多个文件，通常仍是 A。

## 2. 任务执行节奏

### 开始

任务状态和交接统一使用根目录 [STATUS.md](../STATUS.md)，研究任务同时遵守 [research/README.md](../research/README.md)。协调者应在委派说明中传递要求，执行者写独立实验目录，共享状态由协调者串行更新；不另建平行进度文件。

1. 读取 `AGENTS.md`，判断所处阶段、变更边界、权限等级和应阅读的 `docs/` 文件。
   同时检查 `docs/users_idea/` 文件清单和内容哈希，对照 STATUS 的已读快照，阅读更新并评估任务影响；关键设计和交接前再次检查。保留用户原稿，落实状态与理由到 STATUS，并向执行者传递相关内容。
2. 查实际源码、测试、CMake、依赖与 `git status`，不能将文档里的规划目标视为已经实现。
3. 如果是简单局部工作，直接实施；多文件、高风险或需要选型的工作，列简短计划、验收标准和需决定的问题。
4. 如果遇到**真正阻塞当前任务安全 / 正确性 / 性能的必需环境缺口**，及时提供安装 / 验证方案；不相关缺口留给任务总结即可。

### 实施

1. 先写清楚可测试的行为 / 错误语义；小步修改，不顺手引入无关技术栈或未来插件框架。
2. 采用最小必要复杂度：同一模块内部先用简单结构；确有两个独立消费者或生命周期边界时才引入共享接口。
3. 执行目标工具链的真实构建和相关测试；遇到失败查根因，不关闭警告、不跳过断言、不吞第三方错误。
4. 发现新风险时按权限重新分级，隔离未授权部分，完成仍可合法验证的独立工作；不要因一个 C 级待确认动作停下所有 A 级改动。

### 交付

报告保持简洁但可追溯：

```text
【目标 / 状态】完成、部分完成或阻塞
【变更】文件 / 模块、主要功能和设计选择
【风险 / 兼容】安全、格式、API、性能与依赖影响
【验证】实际命令及通过 / 失败的输出摘要
【未验证 / 环境】缺失项、安装建议和验证步骤
【待确认】仅列真正需要授权的决定
【下一步】一项最小可验收工作
```

不得编造实际执行结果。未运行 Sanitizer / Fuzz / Release 测试需要标注“未运行”，不能用“应该可以”代替证据。

## 3. 依赖缺失时的决策算法

```text
发现缺失项
  ├─ 与当前任务无关？→ 不阻塞；必要时总结建议
  └─ 当前任务必需？
       ├─ 可在授权范围内完成非破坏性项目局部配置？
       │    → 配置并测试，报告完成情况
       └─ 涉及系统安装 / 权限 / 许可证或改变承诺？
            → 报告安装与验证方案，等待授权
            → 同时推进不会降低标准的独立部分
```

**禁止替代方案陷阱**：如果应安装受维护的压缩库、动态分析器或正确的 ABI 工具链，不得静默换成没有相应功能 / 性能 / 安全保证的简陋实现；若确有多个性能与安全等效选项，比较证据后按 B 级处理。

## 4. 架构决策记录（ADR）

适用情况：冻结格式、种子生成器协议、Windows 解压策略、依赖管理器 / triplet、性能默认值的长期变化、公共 API 的重要演进。

建议在 `docs/decisions/` 新建有编号的 Markdown（目录暂未创建，可在第一次 ADR 时建立）：

```markdown
# ADR-XXXX：<决定名称>

状态：提案 / 已接受 / 已废弃
日期：YYYY-MM-DD
背景与问题：
必须满足的正确性 / 安全 / 兼容性条件：
候选方案和证据：
选择与理由：
受影响模块 / 外部格式：
迁移、回滚与测试计划：
授权 / 审批记录（如属于 C 级）：
```

ADR 一旦被接受，Agent 应按其执行；不得用新文档或随手改代码绕过此前决策。若证据变了，提交替代 ADR，而不是静默覆盖。

## 5. 项目命名与文档维护

- **当前统一名**：SeedArc — Seed-Driven Adaptive Compression。
- 二进制 / CLI：`seedarc`；建议 CMake 目标：`seedarc_cli`；核心库示例：`libseedarc`；仓库 / 目录：`SeedArc`。
- 早期构想文档使用旧名是**历史事实**，不是新的命名来源。保留其研究问题和未决事项，但新代码 / 文档不要沿用旧软件标识。
- `AGENTS.md` 保持简短，放“必须、禁止、审批、路由”；具体技术细节维护在对应 `docs/`。避免相同参数在多份规范中互相冲突。
- 环境版本只作为 `development.md` 的日期快照；实际选择以构建 / 版本检查为准。构建 / 依赖事实应最终固化到 `CMakePresets.json`、`vcpkg.json` 等机器可检查的配置中。

## 6. Git 与文件处理

- 修改前检查 `git status --short`，保留用户未提交变更。未得到明确授权不得执行破坏性 Git 命令或删除整个目录。
- `.gitignore` 不能全局忽略 `*.md` 而致使规范失去版本追踪；修改时应**合并**现有规则，不覆盖用户自定义忽略项。
- 跟踪 `AGENTS.md`、`docs/**/*.md`、重要设计 / 兼容性文档；忽略构建输出、IDE 缓存、私有 `CMakeUserPresets.json`，不要自动上传私密本机配置。
- 任何新依赖须记录上游来源、许可证、版本固定策略与真实构建测试；不得凭名字猜 port / target / ABI。

## 7. 给 Agent 的防过度工程检查

开始设计新抽象前，必须能回答：

- 当前的真实用例是什么？是否已有标准库 / 简单模块足以满足？
- 不引入抽象会出现哪一个具体的重复、错误边界或测试障碍？
- 新层带来怎样的生命周期、错误传播、性能成本和兼容承诺？
- 是否有可运行的测试或 profile 证明它值得存在？

如答案只是“未来可能有用”，暂不引入。**可靠的少量代码，优于没有证据的通用框架**。
