# ADR-0002：M2 Store 归档的设计约束

状态：**已按第 8 节实现为 M2 实验原型，待用户验收**；第 1–7 节是实施前的约束清单，第 8 节记录实现时确定的字节布局与取舍。仍为 experimental、未冻结。日期：2026-11-11。

输入：[开发计划 M2](../development-plan.md)、[归档要求](../archive-format.md)、[ADR-0001](0001-experimental-container-and-output.md)，以及外部审查 [docs/review_results/SeedArc_项目代码审查.md](../review_results/SeedArc_项目代码审查.md)（采纳情况见 STATUS）。

## 1. 统一解析与验证路径

`verify` 与 `extract` 共用同一条解析 / 校验 / 解码管线，只在最后一步分叉（丢弃字节或安全写出）。顺序固定：

1. 读取并校验 96 字节头部（ADR-0001），先做全部限额与 checked arithmetic 检查。
2. 读取恰好 `index_bytes` 的索引；长度不足即为截断错误，不按声明值预分配超过限额的内存。
3. 解析条目与块表：每个字段先校验范围，再做路径校验（`validate_archive_path` / `validate_manifest_paths`），然后检查文件到块的映射：每块恰好属于一个文件、按顺序覆盖、无重复 / 悬空引用 / 重叠 / 未声明的数据区域、每个文件的块长度之和等于其声明大小。
4. 有界解码：逐块读取，校验存储长度、原始长度与块 CRC32C；累计输出不超过头部声明和限额。
5. 校验通过的字节才交给输出阶段；任何一步失败都不报告成功。

索引必须**整体校验完毕**后才开始写出任何文件，路径冲突和映射错误不能在写出一半时才发现。

## 2. 解压事务语义

区分两种目标，并在 CLI 与文档里如实说明：

| 目标 | 语义 | 失败时 |
| --- | --- | --- |
| 新目录（默认、推荐） | 在目标父目录下创建唯一的临时目录，全部文件写入并校验后，以无替换方式把临时目录改名为目标名 | 目标名从未出现；按句柄逐项清理临时目录中本次创建的对象 |
| 已有目录（需显式选项） | 逐文件无覆盖写入，同时维护**创建清单**（本次创建的文件 / 目录句柄） | 尽力回滚：只删除清单内、仍由本次句柄持有的对象，逆序清理；**不保证原子性**，清理失败要逐项报告 |

- 两种方式都不覆盖已有文件；冲突在写出前通过预检查发现，写出时仍以 `FILE_CREATE` 兜底。
- 回滚绝不按路径删除，也不删除不在清单内的对象（避免误删用户文件）。
- 取消（`ErrorCode::cancelled`）与 I/O 失败走同一清理路径，但错误码不同。
- 进程被强杀时无法清理：新目录模式只会留下带固定前缀的临时目录，CLI 文档说明如何识别；不做崩溃恢复日志（超出 M2 范围）。

## 3. 有界流式写出

`SafeOutputDirectory::write_new_file` 的 4 MiB 整体缓冲上限只适用于 M1 原型。M2 新增流式会话：

1. 打开会话即创建临时文件（与现有原语相同的句柄相对、独占打开、同卷校验）。
2. `append(span)` 逐块写入并增量计算 CRC32C，每次调用检查单文件与累计输出预算。
3. `commit(expected_size, expected_crc)` 先 flush，再核对大小、CRC 和读回结果，最后做 NT 层无替换改名。
4. 会话析构但未 commit 时按句柄删除。
5. 读回校验对大文件是一次完整的再读，开销要记录；是否保留读回由 M2 实测决定，不预设。

现有单文件原语保留，在内部改为基于会话实现，以免出现两套提交逻辑。

## 4. 累计资源预算

在 ADR-0001 的单项限额（已保证 `limits_are_coherent`）之上，M2 引入一个解码预算对象，并明确每项在哪个阶段扣减：

| 预算 | 扣减时机 | 候选默认 |
| --- | --- | --- |
| 索引常驻内存 | 解析前，按 `index_bytes` 加上解析结构的上界 | 不超过 `max_index_bytes` 的固定倍数，实测后确定 |
| 块缓冲 | 每块一次，复用缓冲 | `max_chunk_bytes`（4 MiB） |
| 总解码输出 | 每块解码后 | `max_total_output`（8 GiB） |
| 同时打开的句柄 | 创建目录 / 文件时；目录树深度受 ADR-0001 限制 | 深度上限加上常数 |
| 临时磁盘 | 写出前，按声明总输出估算；可用空间不足时提前失败 | 不另设上限，失败要可清理 |

错误路径上释放资源依赖 RAII；每项预算都要有“恰好等于上限”和“上限 + 1”的测试。

## 5. 压缩侧输入枚举

- 输入为一个文件或目录；按规范 UTF-8 路径字节升序枚举（ADR-0001 的排序候选），不依赖文件系统返回顺序。
- 拒绝符号链接、junction、其他重解析点和特殊文件（不跟随）；空目录保存为显式条目；时间戳 / 权限不保存。
- **输出归档不得被枚举为输入**：输出路径位于输入树内时，以文件 ID 排除，不靠字符串比较；在临时文件中写出，完成后无替换提交。
- 读取期间文件变化：记录打开时的大小与最后写入时间，读完后复核，不一致即失败（不写出伪装成功的归档）。
- 文件内容有界读取，固定分块（默认 1 MiB）。

## 6. 错误码与 CLI 退出码

- 取消使用 `ErrorCode::cancelled`（已在 M2 前加入），不再归入 `io_error`。
- CLI 退出码候选：0 成功；1 数据或校验错误（`malformed_archive`、`integrity_error`）；2 用法错误；3 未实现；4 取消；5 I/O、冲突、资源与路径错误。实现时随 CLI 测试固定，属于外部契约，冻结前需确认。

## 7. 验收测试（对应开发计划 M2）

逐字节往返：空归档、空文件、空目录、单块 / 多块、嵌套目录、非 ASCII 名称、大量小文件、高熵数据、恰好分块边界的文件。负面：截断头 / 索引 / 数据、索引字段越界、重复 / 悬空 / 重叠块引用、大小写冲突路径、路径穿越、超限声明、CRC 损坏、已有文件冲突、受控 I/O 失败与取消（复用 ADR-0001 的故障注入钩子），失败后检查无残留。索引解析加入 libFuzzer 目标并保存回归语料。验证有界内存（记录峰值工作集）。

## 不在 M2 范围

Zstd / LZMA2（M3）、种子与策略（M4）、多线程、崩溃恢复日志、非 Windows 路径规则（Linux CI 的前置条件）、CRC32C 加速（先测量）。

## 8. M2 实现修订（2026-11-11）

本节记录实现时确定的字节布局和对上文的取舍。全部仍为 experimental、未冻结；实现位于 `seedarc::experimental`，对应代码与测试见 [M2 验证记录](../m2-validation.md)。

### 8.1 归档布局

```text
[96 字节头部（ADR-0001，字段不变）][data_bytes 的块数据][index_bytes 的索引]
```

索引放在数据**之后**。头部各字段（条目数、块数、数据与输出总量、索引长度）在枚举输入后即可确定，不依赖文件内容，因此写出端只需顺序追加：头部 → 各块 → 索引（含块 CRC）。读取端按 `96 + data_bytes` 定位索引，并要求归档总长度**恰好**等于 `96 + data_bytes + index_bytes`（更短为截断，更长为未声明数据，均拒绝）。归档无条目时索引为空（0 字节），整个归档就是 96 字节头部。

索引非空时依次为：条目记录（规范顺序）、块记录、4 字节 CRC32C（覆盖此前全部索引字节）。整数均为小端。

| 条目记录偏移 | 字节 | 字段 |
| --- | --- | --- |
| 0 | 4 | path_bytes（1–4096） |
| 4 | 1 | kind：0 文件，1 目录 |
| 5 | 3 | 必须为零 |
| 8 / 16 / 24 | 各 8 | size / first_block / block_count |
| 32 | path_bytes | UTF-8 路径，`/` 分隔，无终止符与填充 |

| 块记录偏移 | 字节 | 字段 |
| --- | --- | --- |
| 0 / 8 / 16 | 各 8 | data_offset（相对数据区）/ stored_size / raw_size |
| 24 / 28 | 各 4 | codec_id（仅 0 = Store）/ codec_config_id（仅 0） |
| 32 | 4 | 原始字节的 CRC32C |
| 36 | 12 | 必须为零 |

`fuzz/make_corpus.py` 是按本节独立编写的 Python 编码器（不共享 C++ 代码），其产物被 C++ 读取端接受并正确解出，作为线格式的交叉验证；`tests/index_tests.cpp` 另有固定字节向量。

### 8.2 规范形式（读取端强制，写出端保证）

- **条目顺序**：按路径逐段比较，每段按 UTF-8 字节序（等价于把 `/` 视为小于任何其他字节的字节序）。这是深度优先的前序遍历：目录之后紧跟其整棵子树。ADR-0001 的候选是“整条路径字节升序”；改为逐段比较是因为它让解压端只需维护一个目录句柄栈，每个目录在其内容写出期间始终被固定（不可改名 / 替换），不需要关闭后再按名字重新打开。严格递增同时排除了重复路径。
- **显式父目录**：每个条目的父目录必须是更早出现的目录条目，写出端为所有目录（含非空目录）写条目。于是解压的创建清单恰好等于条目表，不存在隐式创建的目录。
- **块归属**：`first_block` 必须等于此前条目块数之和（目录也一样），`block_count` 必须等于 `ceil(size / chunk_size_bytes)`，文件除最后一块外每块恰为 `chunk_size_bytes`。因此每块恰属一个文件、按序覆盖、无悬空 / 重叠引用，所有块与输出字节都被条目表覆盖。空文件没有块。
- 目录的 size 与 block_count 必须为 0；保留字节必须为零；路径经 `validate_manifest_paths`（NFC、禁用字符 / 设备名、大小写冲突、文件被当作目录）。

接受的索引重新编码后与输入逐字节相同（Fuzz 目标持续检查这一性质）。

### 8.3 对上文各节的落实与差异

| 节 | 落实 | 未做 / 差异 |
| --- | --- | --- |
| 1 统一管线 | `verify_archive`、`verify_archive_bytes`、`extract_archive` 共用同一个 `run_pipeline`，只有接收已校验字节的 sink 不同；索引整体校验通过后才创建任何输出 | — |
| 2 事务语义 | **新目录模式**：`create_staging_child` 在目标父目录下建随机名暂存目录，全部写入并校验后以 NT 层无替换改名提交；失败 / 取消时按创建清单逆序清理，每个对象经句柄相对打开并核对卷与 128 位文件 ID 后才标记删除，不按路径、不递归删除，清理不完整会在错误信息中报告 | **已有目录模式未实现**：目标已存在一律 `output_conflict`。它需要为每个已创建文件保留句柄或另行设计身份记录，留待有实际需求时再定；崩溃恢复日志仍不做 |
| 3 流式写出 | `SafeOutputFile`：`append` 增量 CRC32C，`commit(expected_size)` flush、核对大小、**整文件读回并与增量 CRC 比较**、无替换改名；未提交即析构则按句柄删除。`write_new_file` 已改为基于会话实现，原有故障注入测试全部保留 | 读回目前保留；开销见验证记录。`commit` 不另收调用方 CRC：块 CRC 已在写入前逐块校验，会话自己的 CRC 用于读回比对 |
| 4 资源预算 | 索引（≤ `max_index_bytes`，且只在确认归档实际长度后分配）、单块缓冲（≤ `max_chunk_bytes`，复用）、总输出 / 数据 / 条目 / 块数均有“恰好等于上限”和“超 1”测试（读、写两侧）；同时打开的目录句柄 ≤ 路径深度；峰值工作集有实测上界断言 | **未做独立的“解码预算对象”**：各项由头部限额与管线结构直接保证，没有需要跨阶段累计扣减的第二个消费者。**未做可用磁盘空间预检**：空间不足表现为写失败并走同一清理路径（已由故障注入覆盖）。索引解析的常驻内存上界未单独测量 |
| 5 输入枚举 | 根对象之下全部经父目录句柄相对打开（`OBJ_DONT_REPARSE`）；符号链接 / junction / 其他重解析点一律报错拒绝；跨卷拒绝；空目录为显式条目；输出归档的临时文件在枚举前创建，按卷 + 文件 ID 排除；读取前核对文件 ID、大小、最后写入时间，读完后再核对一次并确认 EOF；文件以不共享写的方式打开 | 被其他程序以写方式打开的输入文件会使整次压缩失败（共享冲突），这是有意的严格行为；不可表示的名字（非 NFC、含 `~`、保留设备名等）报错而不是改名或跳过 |
| 6 退出码 | 0 成功；1 `malformed_archive` / `integrity_error` / `arithmetic_overflow`；2 用法错误；3 未实现（`search`、`benchmark`）；4 取消；5 其余（I/O、冲突、限额、路径、不支持的特性） | 仍是候选，未冻结；`arithmetic_overflow` 与 `unsupported_feature` 的归类是本次补充 |
| 7 验收测试 | 见验证记录 | 见验证记录的“未验证 / 限制” |

### 8.4 暂存树发布完整性与取消（验收修复，2026-11-11）

独立验收（[记录](../m2-acceptance.md)）发现：已提交文件在发布前可被改写、暂存目录可被加入外来条目，且空归档忽略预先取消。修复后的策略：

1. **访问保护（无竞态窗口）**：`create_staging_child` 在创建暂存目录的同一次 `NtCreateFile` 中设置受保护 DACL，只授予当前令牌用户、SYSTEM、Administrators 完全控制，OI|CI 继承到其下所有对象。能写目标父目录的其他主体从创建到发布都无法打开、写入或向暂存树添加对象。
2. **发布前完整复核**：关闭全部子句柄后、改名前，按条目前序遍历暂存树（每层至多一个句柄）：每个目录必须**恰好**包含本次创建的名字（精确拼写，不多不少）且无命名数据流；每个文件在拒绝写 / 删共享下重新打开，核对卷 + 128 位文件 ID、链接数 1、无命名流、大小及整文件 CRC32C。不一致即 `integrity_error`，走原回滚路径（外来对象保留并报告清理不完整）。
3. **取消**：`run_pipeline` 入口与条目循环结束后检查取消；`ExtractSink::commit` 在复核中和改名前再检查。空归档 / 仅空文件的 extract 与 verify 预取消均返回 `cancelled`，目标不出现。
4. **信任边界与剩余风险**：同一用户、SYSTEM、Administrators 属于受信主体（它们本可调试本进程或直接改发布结果）；受信主体在复核之后、改名之前的修改，以及保留可写内存映射的修改，不在保证范围内。NTFS 不允许在子对象句柄打开时改名目录，所以无法持句柄跨越改名；也不为此持有全部文件句柄（违反句柄预算）。
5. **可见影响**：发布后的目录保留上述私有 DACL，**不再继承目标父目录的 ACL**（共享目录中其他用户将无法读取解压结果）。**用户已于 2026-11-11 确认接受此行为**；若将来需要恢复继承，需另行设计不跟随重解析点的 ACL 传播。
6. **代价**：解压时每个文件多一次完整读取（写入、提交读回、发布前复核共三遍 I/O），尚未测量。

单输入为文件时，归档含一个以该文件名命名的条目；输入为目录时，条目相对该目录（不含目录自身的名字）。时间戳、属性与权限不保存。
