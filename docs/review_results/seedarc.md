# SeedArc 项目进度盘点与下一步推进计划

## 项目当前阶段总览

**SeedArc** 目前正处于从**核心算法验证（研究主线）向生产工程化过渡**的关键分水岭：
* **已完成基建**：跨平台基础建设（POSIX/Linux 移植、远端印度服务器验证）已基本就绪；共享字典在研究容器中已取得比 LZMA2-6 小约 16% 的明确收益（`DEV-013`）。
* **当前核心卡点**：亟需通过 **G5（带预算搜索的种子）** 补齐 `B2-r5` 消融实验闭环，验证“种子”机制的独立价值，并在定型生产级容器格式前完成小文件场景下与固实压缩的横向摸底。

## 二、 下一步推进路线图（建议执行顺序）

### 第一步：清扫基线环境（速战速决）
在编写新代码和启动长时实验前，先清理 **第 5 项（零碎收尾）**，确保所有环境的 `main` 基线干净一致：
- [ ] **同步 WSL 仓库**：将停留在 `linux-l2l3` 的克隆切回并同步到最新 `main`。
- [ ] **排查 Linux 测试残留**：在干净分支上复现并定位那处未查明的测试残留（确认是临时文件未清理还是异常退出所致），避免后续在服务器上跑长时测试时堆积垃圾文件或污染实验结果。
- [ ] **跑通静态检查**：完成 POSIX 源文件的 `clang-tidy` 检查并清理告警，锁定工程基线。

### 第二步：实现 G5 + 启动印度服务器压测（核心攻坚）
将 **第 1 项** 与 **第 2 项** 捆绑推进，这是当前价值最高的主线任务：
- [ ] **在 `r2 dev` 上实现 G5**：严格按照 `seed-ablation r2` 的设计完成带预算搜索的种子逻辑。本地仅使用 `r2 dev` 进行功能验证与小规模调优，**严禁触碰已使用过的 `r2 test`**。
- [ ] **准备全新留出集（Holdout Set）**：趁代码开发和服务器调试的空档，构建用于正式评估的新语料库。
- [ ] **印度服务器长时搜索与压测**：将 G5 的高耗时预算搜索部署至印度服务器运行，既获取 `B2-r5` 缺失的消融实验数据，又同步完成服务器在高负载下的内存、CPU 与 I/O 稳定性压力测试。

### 第三步：完成阶段 D 固实压缩对照（防返工缓冲）
在将共享字典正式推入生产路径（第 4 项）之前，先插队完成 **第 3 项（固实压缩对照）**：
- [ ] **小文件密集场景基准对比**：对比“固实压缩（Solid）”与“共享字典”在压缩率、内存开销与随机读取/解压延迟上的表现。
- [ ] **架构边界评估**：把字典搬进生产路径属于 **C 级架构改动**（涉及二进制格式定型、流式写出、原子提交）。提前明确固实压缩与共享字典是替代关系还是互补关系（例如是否共用同一套分块/流式容器机制），可避免生产格式定型后二次返工。

### 第四步：拍板 ADR 与字典生产化落地
当 G5 明确了种子的独立价值，且阶段 D 厘清了共享字典与固实压缩的边界后，正式启动 **第 4 项**：
- [ ] **撰写并评审 ADR**：敲定最终生产容器格式（是否同时容纳字典与种子元数据、流式分块结构等）。
- [ ] **工程化实现**：完成流式写出（Streaming Write）与原子提交（Atomic Commit）改造，将 `DEV-013` 验证的 16% 压缩率收益正式合入生产主线。

## 三、 待拍板决策事项（Action Required）

在正式启动前两步工作前，以下两个关键节点需要公子定夺：

1. **G5 正式评估的新留出集语料来源**：
   * **方案 A（本机数据抽样）**：构建速度快，贴近真实个人使用场景。
   * **方案 B（下载外部公开标准语料）**：客观性与可复现性更强，便于横向对标。
   * **方案 C（混合配比）**：兼顾真实工作负载与标准基准测试。
2. **第 4 项（字典进生产）的启动时机**：
   * **稳妥路线（推荐）**：等 **G5 消融实验 + 固实压缩对照** 结论全部产出后，再统一设计生产容器格式并编写 ADR。
   * **并行路线**：现在先行起草一份仅针对共享字典的 ADR 草案与流式写出接口设计，后续根据实验结果微调。
